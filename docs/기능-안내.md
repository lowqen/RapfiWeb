계획한 단계(W0~W10)를 모두 마쳤다. 모든 화면이 실물이고 자리표시자는 없다.

**한국어 · 영어(W10).** 브라우저 언어가 한국어 계열이면 한국어, 아니면 영어로 뜬다. 설정 ▸ 자주
쓰는 설정 ▸ 언어로 바꾸면 곧바로 바뀌고 이 브라우저에 남는다
(`localStorage` `rapfi.lang`). 문구의 열쇠는 한국어 원문 그대로다 — `t("기보 열기")` 처럼 쓰고 영어는
`src/i18n/en.ts` 한 곳에 있다. 시험(`src/i18n/i18n.test.ts`)이 소스의 모든 `t()` · `msg()` 를 훑어 영어가
빠진 문구 · 영어에 섞인 한글 · 자리(`{n}`) 어긋남 · 쓰이지 않는 줄 · **대시(— · – · 띄어 쓴 « - »)** 를
잡는다. 번역하지 않는 자료(4수 이름 · 선수 이름 · 엔진 원시 로그)는 `lang="ko"` 를 달거나 `<pre>` 에 둔다.
내보내는 Markdown · HTML 리포트도 지금 언어로 쓴다(CSV 는 데스크톱처럼 영어 그대로).

**키보드와 화면 읽기(W10).** 누르면 두는 판(보드 · DB · 정석 · 오프닝)은 Tab 으로 초점을 받고,
방향키로 커서를 옮겨 Enter · Space 로 둔다 — 커서 칸과 그 자리의 돌은 화면 읽기 프로그램이 읽는다.
보드에 초점이 있을 때 방향키는 커서의 것이고, 그 밖에서는 기보 넘기기(← → Home End)다. 확인 상자는
뜨는 순간 초점을 받고(지우기 같은 일은 «취소»에) Esc 로 닫힌다. 바쁜 패널에는 `aria-busy`, 펼침
단추에는 `aria-expanded` 가 붙는다. `scripts/i18n-smoke.ts` 가 영어 화면의 한글 누출 · 대시 · 휴대폰
세로/가로 · 태블릿 폭의 가로 넘침 · 24px 터치 타깃 · 두 테마의 명암비(4.5:1)를 화면마다 재고, 검사기가
눈을 감지 않았는지 스스로 점검한다.

**RenjuNet 통계(W7).** renju.net 기보 화면(<https://www.renju.net/game/>)의 **[XML]** 버튼으로 받은 파일(`.rif`, 43MB)을 **앱의 아무 화면에나
끌어다 놓거나** 연구 ▸ 랭킹 · 오프닝의 「파일 고르기」로 넣으면, 워커가 파일을 바이트 스트림으로 읽어
몇 초 만에(Celeron N4500 4.6초 · 워커 메모리 피크 50~57MB) 통계 팩을 만들고 IndexedDB(`rapfiweb` ▸
`packs`, 15MB)에 둔다 — 다음부터는 바로 뜬다. 오른쪽 아래 카드가 바이트 기준 진행 · 단계 · 경과를
말하고 취소할 수 있다. 연구 ▸ 랭킹은 26주형 · 5수 모양을 판 수 · 흑 점수로, 선수(이름 · 나라) · 그
선수의 색 · 규칙으로 거르고 걸렀을 때는 윌슨 아래 끝으로 승률 순을 준다. 연구 ▸ 오프닝은 국면마다
판 수 · 승무패 · 다음 수(둔 수 ∪ 이론 수)와 그 국면을 지난 대국(선수로 거르기, 누르면 보드에서
열기)을 보인다. 파일이 없으면 내 기보(저장한 기보와 지금 판)로 같은 화면을 채운다. 국면은 64비트
정규 해시로 세며(`src/core/rif`), `pos-key.ts` 와 동치류가 같다는 시험과 실제 파일에서 데스크톱
팩 116,191국면 전부가 일치한다는 대조(`tools/w7/rif-crosscheck.ts`, 로컬 전용)가 있다. **파일과
통계는 이 브라우저 밖으로 나가지 않는다** — RenjuNet 은 비상업 · 오프라인 사용만 허락한다.

**판은 저절로 남는다.** 두고 무른 수까지 IndexedDB(`rapfiweb` ▸ `games`)에 자동 저장되어
새로고침해도 이어진다. 기보는 국면 카드 머리의 «기보» 메뉴 ▸ 「기보 열기」나 판에 파일을 끌어다 놓아 열고,
「.psq 저장」 · 「.sav 저장」으로 지금 판을 내보낸다(Chromium 은 저장 창, 그 밖은 내려받기).
「링크 복사」는 지금 판을 `…/board?p=h8i9j10` 주소로 복사한다 — 어느 화면 주소에 `?p=` 를 붙여도
그 국면으로 열리고, 읽은 뒤에는 주소에서 걷어낸다(새로고침이 그동안 둔 수를 지우지 않게).

**주형 이름과 유불리.** 국면 카드의 「주형」 줄이 1~4수 이름 사슬(예: 천원 › 직접막기 › 소성 › 소기)과
4·5수의 흑 5수 유불리를 보여 준다. 연구 ▸ 오프닝 탭에서는 같은 판으로 이론 다음 수(4수 이름 ·
5수 등급)와 환원(같은 돌, 다른 수순)을 훑는다. 표 둘(`src/core/opening/data/`, 50KB)은 앱이 뜰
때 별도 조각으로 받는다.

**게임 리뷰.** 연구 ▸ 리뷰·증명에서 「지금 판 리뷰」(무른 수까지)나 기보 파일 여러 개를 큐에 넣어
돌린다. 국면마다 엔진이 상위 두 후보를 읽고(`YXNBEST 2`), 데스크톱의 분류기가 수마다 명수 ·
최선 · 실수 · 대실수 · 놓친 승리 등 11등급과 쪽마다 정확도를 매긴다. 리포트는 판 · 형세 그래프 ·
최악의 수 · 수순 표로 보고, CSV · Markdown · HTML(데스크톱과 같은 한 파일 페이지)로 내보낸다.
도는 동안 엔진은 리뷰의 것이다 — 분석과 대국의 엔진 착수는 기다린다. 국면 하나마다 체크포인트를
남겨, 멈추거나 탭을 닫아도 다음에 그 자리부터 잇는다. 고른 리포트의 수순을 판이 따르면 국면 카드의
「평가」 줄에 마지막 수의 등급이 뜬다.

**수순 탐색.** 연구 ▸ 수순은 지금 판의 돌을 정확히 만드는 수순을 센다 — 한 수씩 파고들며 갈래마다
그 뒤의 수순 수와 몫을 보이고, 남은 돌마다 «몇 수째가 될 수 있나»를 단다(규칙: 오프닝 상자 · 2수 H9/I9 ·
중간 오목 금지 · 환원). 20돌이면 1초 남짓이라 계산은 워커에서 돈다.

**국면 증명.** 연구 ▸ 리뷰·증명 아래에서 지금 판의 둘 차례 승리를 증명하거나 반증한다. 공격 마디는
`yxnbest k`, 방어 마디는 `YXSEARCHDEFEND`, 메이트만 결론으로 친다. 판 위에 뿌리 후보마다 상태와 탐색
중인 줄을 그린다. 리뷰와 같은 엔진 자물쇠라 둘은 겹쳐 돌지 않는다. DB 가 붙어 있으면 데스크톱처럼
마디마다 DB 를 먼저 묻고(`yxquerydatabaseone`), 증명된 메이트를 DB 에 적는다(둘 차례 승 = `L`) —
붙어 있지 않으면 결론은 그 실행 안에서만 쓰인다.

**데이터베이스(W8).** 엔진의 yixindb 를 쓴다. 파일(`rapfi.db`)은 IndexedDB(`rapfiweb` ▸ `dbfiles`)에
두고, 엔진이 뜰 때마다 엔진 메모리 FS 에 써 넣은 뒤 `info usedatabase 1` 로 연다(엔진 `-w8` 이
Emscripten `FS` 를 내보낸다). 저장은 `YXSAVEDATABASE` 뒤 엔진이 쓴 파일을 읽어 IndexedDB 에 덮어쓴다 —
자동 저장(분)과 탭을 숨길 때의 저장이 있고, **저장하지 않은 변경은 엔진을 다시 띄우면 사라진다.**
DB 화면은 지금 판의 자식 값 · 칸 글자를 판에 그리고, 국면 기록(라벨 · 값 · 깊이) · 주석(여러 줄 · 한글) ·
칸 글자를 고치고, 이 국면/아래 분기(필터 7종)를 지우고, `.db` 를 올리고 내려받고, CSV(`dbtotxt all`)로
내보낸다. 고치기 · 저장은 엔진의 생각을 끊으므로 분석은 먼저 멈추고, 리뷰 · 증명 중에는 받지 않는다.
**보드 화면에서도 보인다** — DB 가 붙어 있으면 판이 바뀔 때마다 지금 국면을 묻고, 국면 카드에 주석을,
[분석] 탭의 판에 자식 값 · 칸 글자 칩을(엔진 칩보다 앞선다), 평가 바에 자식 값으로 읽은 국면 값
(`positionValue`, 데스크톱 `evalbar_update_from_db`)을 «DB» 표시와 함께 그린다 — 엔진이 그 국면을 읽는
동안은 엔진의 실시간 값이 앞선다. 대국에서 엔진이 수를 생각하는 동안과 리뷰 · 증명 중에는 묻지 않는다
(질의가 줄에 서면 워커가 도는 탐색을 비키게 해, 무제한 착수가 「지금 두기」 없이 둬 버린다).

**공식 정석 커리큘럼.** 정석 화면의 첫 탭이다. 관리자가 저장소에 실은 `public/joseki/curriculum.json` 을 읽기
전용으로 배운다 — 체스닷컴 레슨처럼 코스 목록 › 코스(「시작」 · 레슨 카드) › 레슨(판 + 코치 말풍선 칸), 레슨마다 **살펴보기**(트리 · 판 · 해설, 좋은 수 · 나쁜 수 · 함정수 · 응징 표시)와 **학습**
(학습자 색의 수를 직접 맞힌다: 추천 수 · 좋은 수는 정답, 나쁜 수 · 함정은 해설과 응징을 보이고 다시, 두 번 틀리면 힌트,
끝나면 첫 시도 정답률이 점수 — 진도는 이 브라우저에). 코스 · 레슨마다 링크가 있다(`/joseki?course=<id>` · `?lesson=<id>`, 학습은
`&mode=learn` · «링크 복사»). 설계 [`공식-정석-설계.md`](공식-정석-설계.md), 관리
[`공식-정석-관리.md`](공식-정석-관리.md).

**정석(W9).** 정석 하나가 문서 하나다(`rapfiweb` ▸ `joseki`). 판을 누르거나 `h8 i9 j10` 을 적어 수를
넣고(이미 있는 수면 그 갈래로 간다), 갈래를 주 변화로 올리고 순서를 바꾸고 지운다. 수마다 평가 기호
(`!! ! !? ?! ? ??`)와 마크다운 메모(굵게 · 기울임 · 목록 · 링크 — `h8` 같은 좌표는 누르면 그 수로)를 단다.
분류는 주 변화의 주형 이름(이름 사슬 · 26주형 · 흑 5수 등급)에서 저절로 붙는다. 모든 마디의 정규
국면 키를 색인(`josekiIndex`)에 두어 **보드의 지금 국면으로 정석을 찾는다** — 뒤집거나 돌린 판도 걸린다.
JSON 으로 주고받고(가져오기는 검증), 변화 하나를 `.psq` 로, 기보(.psq · .sav · .pos)는 정석 초안으로 들인다.

**데스크톱 설정 파일(W5b).** 설정 ▸ 시스템에서 `settings.txt` · `settings_dev.txt` 를 가져오고 내보낸다.
67칸 중 웹이 뜻을 가진 33칸(엔진 · 대국 · 표시 · 리뷰 · 증명 · DB)이 웹 값이 되고, 나머지(언어 · 글꼴 ·
툴바 …)는 그대로 들고 있다가 내보낼 때 돌려준다 — 가져와서 곧바로 내보내면 바이트가 같다. 웹 한계
(해시 512MB · 깊이 225 · 멀티 PV 10 · 스레드 16)는 가져올 때 말하고, 내보낼 때 PC 의 더 큰 값을 깎지
않는다. 27행(다크 모드)은 시스템 따름을 이기고 테마를 고정한다.

**링크로 열기 전 판.** `?p=` 링크가 두던 판을 덮으면 그 판을 따로 보관하고 보드 옆 칸에
「두던 판으로 돌아가기 · 버리기」를 띄운다(고를 때까지 남는다).

엔진은 **앱이 뜨면 뒤에서 자동으로 기동한다.** 상단 바의 엔진 표시가 단계(가중치 받기 →
엔진 → 예열 → 준비)를 말하고, 그동안에도 판은 바로 둘 수 있다. 20MB 가중치는 처음 한 번만
받고 그 뒤로는 캐시에서 읽는다. 끄려면 설정 ▸ 「앱을 열면 엔진 시작」, 한 번만 건너뛰려면
주소에 `?autoboot=0`. 산출물이 없는 개발 환경에서는 기동이 「엔진 오류」로 조용히 끝난다.
상단 바 밑의 진행 줄은 250ms 안에 끝나는 기동에는 나타나지 않고, 나타나면 적어도 0.9초 머문 뒤
끝날 때 왼쪽부터 차오르고 천천히 사라진다(흐름을 멈춰 세우지 않는다 — 예전에는 그 순간 얼어붙어 깜빡였다).
엔진 표시의 점은 기동 중에 주황으로 **멈춰 있다** — 예전의 투명도 맥박은 처음 접속의 수 초 동안 이어져
눈이 아프다는 의견에 뺐다.

**엔진 선택.** 설정 ▸ 자주 쓰는 설정 ▸ 엔진의 드롭다운으로 자동 · Multi-thread · WASM Relaxed-SIMD ·
WASM Standard SIMD 중에서 고른다. 바꾸면 떠 있는 워커를 깨끗이 내리고 그 바이너리로 다시
띄운다 — 켜 둔 분석은 새 엔진이 이어 읽는다. 이 환경에서 못 쓰는 항목은 까닭과 함께 잠긴다.

**보드는 [분석] | [대국] 두 탭이다.** 처음 열면 분석 탭이고, 고른 탭은 이 브라우저에 남는다. 판(기보)은
함께 쓰고 엔진의 쓰임만 갈린다. 상단 바는 제목 · 엔진 표시 · 테마뿐이다 — 엔진 선택과 언어는 설정으로 옮겼다.
판 위아래에는 아무것도 두지 않아 판이 화면 높이를 다 쓴다: 탭 · 새 판 · 진영 전환은 오른쪽 칸 맨 위, 기보 이동은
맨 아래다(휴대폰 세로에서는 판 밑으로 이동 바 · 탭 · 카드). 판 위의 값(승률 · W/L · DB 값 · 정석 기호)은 동그라미
없이 **글자만** 쓴다 — 짐 파랑 → 막상막하 초록 → 이김 빨강, 어두운 외곽선(데스크톱 Yixin 의 판 위 숫자처럼).

| 탭 | 옆 칸 | 엔진 |
|---|---|---|
| 분석 | 최선수 · 승률 · 평가 · 깊이(시간 · 노드 · 속도는 «세부 수치») · PV · 형세 그래프 · 접힌 «분석 설정»(분석 시간 · 후보 수) | 국면을 따라 읽는다. 「정지」는 그 순간의 최선수를 둔다(빈 판이면 H8). 엔진 「종료」는 엔진 화면에 있다 |
| 대국 | 흑/백 · 시간 제어(칩 + 직접 입력) · 레벨(노드 수) · 스레드 · 개시 · 기권/무승부 | 제 차례에만 둔다. 빈 판의 흑 첫 수는 묻지 않고 천원(H8)에 곧바로 둔다. 판에 분석 오버레이를 얹지 않는다 |

**국면 카드는 옆 칸 맨 위다**(넓은 화면) — 차례 · 수 · 마지막 수 타일과 주형 · 평가 · DB · 기보 줄, 파일 ·
링크 버튼. 좁은 화면(휴대폰 세로 · 낮은 가로)에서는 옆 칸이 짧아 카드가 탭의 카드 뒤로 물러서고, 대신
국면 요약 한 줄(차례 · 수 · 마지막 · 주형 · 유불리)이 옆 칸 맨 위에 붙는다 — 휴대폰 세로에서는 판 바로 밑.

**시간은 직접 적을 수 있다.** 착수 시간 · 분석 시간 · 리뷰 국면당 시간 · 증명 예산의 칩/눈금 옆
「직접」 칸에 `2.5` · `1500ms` · `2분`(`2min`) · `무제한`(`unlimited`) 처럼 적는다(`src/core/settings/duration.ts`). 범위를
벗어나면 끝값으로 자르고, 음수 · 글자 · 빈칸이면 그 칸의 기본값으로 돌리며 까닭을 잠깐 띄운다.

탭을 바꾸면 대국 → 분석은 엔진이 생각하던 수를 **버리고**, 분석 → 대국은 분석을 **멈추기만**
한다(최선수를 두지 않는다). 무르기·처음으로 직후에는 앞날 국면의 값 칩 · PV · 평가가 판에
남지 않는다 — 엔진의 답에는 국면 키가 붙어 있고 화면은 지금 판의 키와 맞을 때만 그린다.

**이 웹 버전은 렌주 전용이다.** 가중치가 규칙마다 10MB 씩이고 Cloudflare 는 파일당
25MB 가 상한이라, 렌주 흑/백 두 개만 싣는다(`src/core/model/rules.ts`).

## 로컬 개발 환경

필요한 것은 **Node**(CI 는 26, 최소 20.11)와 **pnpm** 둘뿐이다.

```bash
# 1. Node 26 — CI(.github/workflows/*)와 같은 주 버전
#    Windows:  winget install OpenJS.NodeJS
#    macOS:    brew install node
#    Linux:    https://github.com/nodesource/distributions

# 2. pnpm — 노드 25+ 에는 corepack 이 딸려 오지 않는다. pnpm 10+ 는 package.json 의
#    packageManager(pnpm@9.12.3)를 읽어 그 판으로 스스로 바꿔 돈다.
npm install -g pnpm

# 3. 의존성
pnpm install

# 4. 개발 서버 — http://localhost:5173
pnpm dev
```

`pnpm dev` 는 먼저 `scripts/gen-tokens.ts` 로 `src/styles/tokens.css` 를 굽고 Vite 를 띄운다.
그 CSS 는 **생성물이라 커밋하지 않는다** — 원본은 `src/core/design/` 의 TS 다.

### 자주 쓰는 명령

| 명령 | 하는 일 |
|---|---|
| `pnpm dev` | 토큰 생성 + 개발 서버 |
| `pnpm build` | 토큰 생성 + 타입 검사 + 프로덕션 빌드 (`dist/`) |
| `pnpm preview` | 빌드 결과를 그대로 띄워 본다 |
| `pnpm test` | 단위 시험 (팔레트 골든 앵커, 프로토콜 직렬화) |
| `pnpm lint` / `pnpm format` | ESLint / Prettier |
| `pnpm check` | 위 전부를 CI 와 같은 순서로 |
| `pnpm gen:tokens` | 토큰만 다시 굽기 |
| `pnpm exec tsx scripts/i18n-smoke.ts` | (빌드 뒤) 다국어 · 반응형 · 접근성 스모크(W10) |

### 엔진(WASM)을 직접 빌드하려면

리눅스 x86_64 가 필요하다(GitHub Actions `ubuntu-latest` 에서 그대로 돈다).

```bash
pnpm engine:build          # tools/build_engine_wasm.sh
```

`out/engine/` 에 나온 것을 `public/engine/` 으로 옮기면 앱이 그걸 쓴다.
`.env` 의 `VITE_ENGINE_BASE_URL` 로 다른 경로를 가리킬 수도 있다.

**빌드하지 않고 받아 쓰는 쪽이 빠르다.** `.js`/`.wasm` 은 이미 저장소에 있고,
20MB 짜리 `.data` 만 릴리스에서 받으면 된다:

```bash
# 태그는 src/engine/engine-manifest.json 의 tag 와 같아야 한다(지금 engine-3c94c2a9-a3)
gh release download engine-3c94c2a9-a3 --dir public/engine --pattern 'rapfi.data'
```

릴리스가 없으면 Actions ▸ **엔진 릴리스 (WASM 산출물)** 을 한 번 돌린다.

## 이 저장소에서 절대 하지 말 것

**RenjuNet 파생 자료(`.rif`, `*.pack`, `freq_data.json`, `renju*.sqlite`)를 커밋하지 않는다.**
라이선스가 «비상업·오프라인 전용, 재배포 금지»를 명시하고, 웹에서는 커밋이 곧
«온라인 시스템에 게시»라 앱보다 더 위험하다. `.gitignore` 와 CI 게이트가 둘 다 막고 있지만,
막는 장치가 있다는 것이 해도 된다는 뜻은 아니다.

가중치(`*.bin.lz4`)는 CC0 라 재배포는 자유롭지만 20MB 라 릴리스 자산으로 나른다.

## 브라우저 요구사항

**WebAssembly SIMD 가 하한선이다.** 비SIMD 변형은 이 엔진 커밋에서 빌드되지 않는다
(`eval/mix10nnue.cpp` 의 `static_assert`). 하향할 변형이 없으므로 미달 브라우저는
안내 화면으로 끝난다.

| | 최소 |
|---|---|
| Chrome / Edge | 97 |
| Firefox | 102 |
| Safari | **16.4** (iOS 16.4 미만은 지원하지 않는다) |

Chrome/Edge 97 · Firefox 102 는 SIMD 가 아니라 **CSP 의 `'wasm-unsafe-eval'`** 이 정한 하한이다(2026-10-10,
`docs/보안-강화-계획.md` Phase 1). 그보다 오래된 브라우저는 이 키워드를 몰라 WASM 컴파일을 막으므로 엔진이
「엔진 오류」로 끝난다.

COOP/COEP 헤더는 **멀티스레드 엔진에만** 필요하다(`public/_headers`). 헤더를 붙일 수 없는
호스팅(GitHub Pages 등)에서는 앱이 단일 스레드 엔진으로 물러선다 — 그래서 정적 파일을 얹을 수
있는 곳이면 어디든 올라간다.
