# 공식 정석 커리큘럼 설계

> 작성 2026-10-11 · 대상: RapfiWeb 정석 화면 · 상태: **설계 확정 → 1차 구현(이 문서의 §6)**

## 1. 목표

초보자도 전문가가 차례를 정해 만든 오프닝 커리큘럼을 **읽기 전용으로 받아** 수순마다의 해설을 읽고,
**직접 맞히며 따라 두는** 학습까지 할 수 있게 한다. 관리자(저장소 주인)는 로컬에서 편집해 저장소의
정적 자산으로 커밋하는 것으로 배포한다. 서버 · 계정 · 데이터베이스는 두지 않는다(정적 호스팅 원칙).

## 2. 권한과 배포 구조

| 누가 | 무엇을 | 어떻게 |
|---|---|---|
| 모든 사용자 | 공식 커리큘럼 읽기 · 학습 | 앱이 같은 출처의 `public/joseki/curriculum.json` 을 받아 읽는다(번들 밖 자산 — 앱 코드와 따로 캐시된다). 고칠 길이 화면에 없다 |
| 관리자 | 커리큘럼 편집 · 배포 | ① 커리큘럼 스튜디오(`/joseki/studio`, `pnpm studio`)에서 코스 · 레슨 · 트리 · 두 언어 해설을 만들고 검사 → ② «저장소에 저장»(개발 서버) 또는 내려받기 → ③ `pnpm curriculum:publish` 가 검사 · 시험 · 커밋 · push → CI · 배포 → 웹과 RapfiDroid 앱이 같은 파일을 받는다 |

**권한의 실제 경계는 git 이다.** 앱의 «관리자 도구»(설정 ▸ 고급 ▸ 시스템의 스위치)는 편집 UI 를 보이게 할
뿐 비밀이 아니다 — 누구나 켤 수 있지만 할 수 있는 일은 JSON 파일을 내려받는 것까지다. 배포본을 바꾸려면
저장소에 쓸 권한이 있어야 하고, `public/joseki/` 는 CODEOWNERS 로 관리자 검토 대상이다(보안 강화 계획 Phase 2
의 규칙 집합과 같은 장치).

## 3. 데이터 구조

```ts
interface CurriculumFile {
  format: "rapfiweb-curriculum";
  schema: 1;
  version: string;          // 사람이 읽는 판 — "2026.10.11"
  courses: Course[];
}

interface Course {
  id: string;               // [a-z0-9-], 파일 안에서 유일
  title: Text;
  level: "beginner" | "intermediate" | "advanced";
  summary: Text;            // 마크다운
  lessons: Lesson[];
}

interface Lesson {
  id: string;               // 파일 전체에서 유일 — 진도 기록의 열쇠
  title: Text;
  summary: Text;
  quiz: { side: "black" | "white" };   // 학습 모드에서 학습자가 맡는 색
  root: CurriculumNode;     // 뿌리(빈 판)
}

interface CurriculumNode {
  move: Move | null;        // 뿌리만 null
  comment: Text;            // 마크다운 — 좌표(h8)는 누르면 그 수로
  mark?: "!!" | "!" | "!?" | "?!" | "?" | "??";
  role?: "trap" | "refute"; // 함정수 · 응징(대응) — 평가 기호와 따로 단다
  children: CurriculumNode[];   // [0] 이 주 변화
}

type Text = string | { ko: string; en?: string };   // 영어가 없으면 한국어
```

- **기존 정석 트리(`JosekiNode`)와 같은 모양**이다(`comment` 가 두 언어를 받을 수 있고 `role` 이 더해진 것뿐).
  그래서 트리 그리기 · 마크다운 · 판 덧그림을 그대로 쓰고, 「내 정석」에서 쓴 트리가 손실 없이 넘어간다.
  `role` 은 내 정석에도 붙일 수 있게 한다(편집기의 «함정 · 응징» 단추).
- **갈래의 뜻**: `children[0]` = 추천 수(주 변화). 다른 자식은 평가 기호로 성격이 정해진다 — `!!` `!` `!?` 는
  «다른 좋은 수», `?!` `?` `??` 는 «나쁜 수», `role: "trap"` 은 «함정수»(그럴듯하지만 걸려드는 수 · 상대가 놓는
  덫), `role: "refute"` 는 «응징 · 대응»(나쁜 수 · 함정을 벌하는 답).
- **검증**(가져오기와 같은 규칙 — `core/joseki/io.ts` 의 `cleanTree` 를 다시 쓴다): 판 밖 · 겹친 수 · 모르는 기호
  는 그 가지째 버린다, 글은 문자열만 · 길이 상한, `id` 형식과 유일성, 학습자가 둘 수가 주 변화에 하나 이상.
  배포 파일은 단위 시험이 매번 검증한다 — 잘못 만든 파일은 CI 를 통과하지 못한다.

## 4. 화면

정석 화면 위에 탭 둘: **[공식 커리큘럼] [내 정석]**(내 정석 = 지금까지의 W9 화면).

배치는 체스닷컴 레슨의 세 층을 따른다(UI 개편, 2026-10-11). 화면은 구조만 정하고 글은 관리자가 채운다.

1. **코스 목록** — 그림 · 제목 · 한 줄의 머리 밑에 코스 카드(첫 레슨 수순의 썸네일 · 제목 · 수준 배지 · 레슨
   수와 진도 · 요약 두 줄 · 진도 막대).
2. **코스**(`?course=<id>`) — 큰 썸네일 · 제목 · 수준 · 설명과 「시작 / 이어서 배우기 / 처음부터 다시」(아직 안 한
   첫 레슨으로), 그 밑에 레슨 카드(번호 · 썸네일 · 제목 · 요약 · 최고 점수).
3. **레슨** — 판이 왼쪽에서 크게, 오른쪽 칸은 ← · 코스 › 레슨 제목, [살펴보기 | 학습] 탭, 코치 말풍선(둘 차례 +
   해설 · 판정), 살펴보기에서는 그 밑에 트리(배지: 추천 · 좋은 수 · 나쁜 수 · 함정 · 응징), 바닥에 진행 막대 ·
   힌트 · 처음부터 · 링크 · 수 이동. 판의 자식 수는 A · B · 기호로 보인다. 두 모드:
   - **살펴보기**: 트리 · 판을 자유롭게 오가며 모든 갈래(악수 · 함정 포함)와 해설을 읽는다.
   - **학습**: 수순을 직접 맞힌다(§5).
4. **진도** — 레슨마다 최고 점수(첫 시도 정답률)와 완료 여부. 이 브라우저에 남는다(`localStorage`
   `rapfi.curriculum.progress` — 사용자별 편의라 서버가 필요 없다).

## 5. 학습(퀴즈) 흐름

```
뿌리 → (학습자 색이 백이면 흑의 주 변화 수를 자동으로) →
학습자 차례: 판을 누른다
  ├─ 추천 수 · 좋은 수(주 변화 또는 !!·!·!?)  → ✓ 해설을 보이고 그 갈래로 진행 → 상대의 주 변화 수를 자동으로
  ├─ 알려진 나쁜 수 · 함정수                 → ✗ 그 갈래의 해설과 응징 수(그 마디의 [0])를 판에 보이고, 다시
  └─ 트리에 없는 수                          → «정석 밖의 수», 다시
  · 힌트: 단추로, 또는 두 번 틀리면 추천 수 자리를 판에 표시
끝(더 둘 학습자 수가 없음) → 점수 = 첫 시도 정답 / 학습자 수, 진도에 기록 · 다시하기
```

판정은 순수 함수(`core/curriculum/quiz.ts`)라 화면 없이 시험한다.

## 6. 1차 구현 범위

| 층 | 파일 | 내용 |
|---|---|---|
| 핵심 | `core/curriculum/schema.ts` · `quiz.ts` | 타입 · 검증 · 두 언어 글 · 퀴즈 판정 |
| 자료 | `public/joseki/curriculum.json` · `data/curriculum.ts` | 배포 파일, 받아 읽기 · 진도 |
| 화면 | `features/joseki/curriculum/*` · `JosekiScreen.tsx` | 탭 · 코스 · 레슨(살펴보기 · 학습) |
| 관리자 | `features/joseki/studio/*` · `core/curriculum/edit.ts` · `audit.ts` · `format.ts` · `scripts/studio-plugin.ts` · `scripts/curriculum-publish.ts` · 설정 «관리자 도구» | 커리큘럼 스튜디오(전체 편집 · 검사 · 미리 보기 · 초안), 저장소 쓰기(개발 서버), 배포 한 줄 — [`공식-정석-관리.md`](공식-정석-관리.md) |
| 검증 | `core/curriculum/curriculum.test.ts` · `scripts/joseki-smoke.ts` | 스키마 · 퀴즈 · 배포 파일 · 이름 일치, 브라우저 흐름 |

### 예시 커리큘럼

배포 파일에는 **규칙과 앱의 분류기에서 나온 사실만** 담은 예시 코스를 싣는다 — 첫 세 수의 개시 규칙(1수 천원 ·
2수 천원 둘레 3×3 · 3수 5×5), 직접 · 간접 개시, 26주형의 대표 수순과 이름(앱의 `opening26` 표 — 시험이 레슨의
수순과 이름이 맞는지 대조한다). 정석의 깊은 수순 · 형세 판단 같은 **전문 해설은 관리자가 채운다** — 근거 없는
이론을 앱이 지어내지 않는다.
